# zombie-escape-study-game

A local browser-based, real-time top-down survival/study game in active development. Nineteen autonomous NPC survivors share a procedurally generated four-floor building with the human. Reach recurring four-seat rooftop helicopters while the horde enters exclusively through the ground-floor entrance.

**Current study flow:** the game occupies one tab; answers and tutoring happen in an ordinary ChatGPT chat beside it. The game receives the attributed conversation in one final completion callback per question. Live question generation and formal learning assessment use separate, bounded tool steps in that same chat. Existing learning evidence and the original roadmap remain intact. The connector is a ChatGPT handoff; it does not certify native ChatGPT Study Mode or grading quality.

## Native chat and role preparation

Press E at a station, then answer in your ChatGPT tab. If the question has not appeared, ask ChatGPT to **get my current game study question**. The connector uses `get_current_study_question` to fetch the issued question. When live study first needs question generation or later needs formal learning assessment, the getter can instead return that captured one-shot job. ChatGPT reads its required context, returns the result with `finish_study_preparation`, and follows the bound continuation to the question or assessment result. No separate polling worker is required for this flow.

Chat normally during the question; no in-game chat composer or per-answer delivery is involved. At the end, ChatGPT calls `finish_study_question` with the exact question identity, outcome, knowledge findings and attributed transcript. A successful tool receipt means the result was sent to the bridge. The game still validates it before granting one key and personal access to a living survivor in the active run. Separate formal assessment determines academic evidence; sending a completion does not certify mastery. After death or extraction, you can finish the same question for learning evidence, with no further world reward. The game becomes a live spectator view, and an unfinished question does not force the run summary over the game. Pause also freezes spectator simulation.

An optional small connection card can deliver newly opened questions, but the normal chat can fetch them without that card. Refresh the connector's tool discovery after updating an older installation so the current getter, preparation, completion and context tools are available. The native flow has automated synthetic coverage; actual ChatGPT activation and semantic quality require separate verification.

Fresh playable runs allow three minutes before the first zombies, then add one every three seconds up to 180 living zombies. NPC reasoning progresses at one-quarter of its former rate; movement and combat stay responsive. The first helicopter arrives after eight minutes, followed by pickups every three minutes. Older saves and reproducible legacy factories retain their original pacing. These defaults are starting values for human playtesting, not a claim that an NPC models human thinking accurately.

Preparation defaults to **Product feature owner · consumer & creative web**: end-to-end feature ownership with frontend depth, appropriate backend correctness and security, and polished user experience, at any company size. The reversible role profile requires 51 core PE objectives through D3. Reference and optional PE topics do not block advancement or appear in random practice. Python interview fundamentals retain all original targets and scheduling, including D4. The Learning continuity inspector can restore **Full original curriculum**; switching preserves issued questions, source definitions, observations, and review dates. Profile completion is displayed separately from original-roadmap readiness. Complete roadmap exports retain the full source curriculum and evidence; finishing the role profile does not mark omitted PE objectives or D4 requirements as mastered.

D1 questions stay bounded. Operational facts such as DNS/HTTPS setup can be supplied; the tutor does not recursively drill into transport internals. Findings distinguish demonstrated knowledge, knowledge necessarily implied by an answer, and explicit gaps. Unasked details remain unassessed. Native intermediate replies avoid game relay overhead, but initial preparation and question delivery, the final callback, and any separate assessment still take time. Metadata timestamps distinguish queue, claim, completion, delivery and application.

## Run

Requires Node.js 22.12+ (developed with Node 26) and npm.

```sh
npm ci
npm run import:curriculum
npm run dev
```

Open http://127.0.0.1:5173. The game fills the window, with floor and survivor status in compact overlays. Press Esc or Pause for Resume, Settings, Restart, and Save and quit. Settings stays inside the pause dialog while the simulation is frozen. Inspection, logs, and diagnostic controls stay hidden from the player interface; coding agents can access them through `window.__deadAir.openAgentMenu()` in a synthetic browser context. The HTTP bridge relay binds only to 127.0.0.1:4318. No API key is needed for development mode. Offline practice lets you read and draft; completing a human puzzle requires the connected AI reviewer.

For a production deployment, run `npm run build` and then `npm start` (stop the dev server first). This serves only `dist`, reconnects the persistent bridge and proxies its API at the same `127.0.0.1:5173` origin, preserving browser saves. HTML and curriculum bypass caches; hashed assets can be cached. `GET /_app-health` reports the running build fingerprint. `npm run preview` is available for temporary bundle previews and does not launch the bridge. Keep the app on port 5173 for the connector's existing consent boundary.

The configured macOS workstation runs production through the `com.jack.zombie-study-escape` LaunchAgent. Before development or browser tests, stop that app service with `launchctl bootout gui/$(id -u)/com.jack.zombie-study-escape`, then run `npm run dev`. After stopping development and rebuilding, restore it with `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.jack.zombie-study-escape.plist`. The separately managed bridge retains its queued requests across app-server changes.

## Controls and force fields

**Study only** opens a neutral **Learning workspace** from the main controls or Pause menu. It freezes and mutes the game, shows your learning progress, and lets you start the next scheduled question without finding a station. Copy the request into ChatGPT and answer there as usual. The dashboard confirms when the result is received and saved, then shows the separate progress assessment state. Failed saves and progress reviews offer retry buttons. Your study view survives reloads; **Exit study view** restores the prior run and pause state. Standalone study questions award no game items, while validated learning still follows the existing assessment process.

New runs use force fields, independent solo terminals and a continuous swarm. Existing saved runs keep their original objects, puzzles and rules; restart from Pause to use the redesign while retaining learning progress and archiving unfinished work.

- WASD or arrows: move. Walk through translucent green fields. Translucent red fields block you; press E nearby to consume one key and grant permanent access to **you alone**. The rear study hall stays green without a pass limit on every floor, so reaching the first puzzle needs no key. Every survivor starts with zero keys; solving a solo puzzle earns the first key. Zombies must physically break either color before crossing.
- Room entrances offer 3–5 free inward admissions by distinct survivors, selected deterministically from the seed. The visible counter never replenishes. When exhausted, the entrance turns red unless you have paid for personal access. The pass is consumed immediately on first touch. The first entrant keeps that crossing; later entrants are pushed back to their approach side even when overlapping the doorway. Physics touch order decides, with a stable actor-ID tie-break for exact ties. Repeated crossings by one survivor cannot drain the quota.
- Forward exits never use the entrance quota. Solving a solo puzzle makes the floor's forward exits green for that solver, grants personal stair access and awards one key. Keys can also unlock an exit early. Other survivors must earn or pay for their own access.
- E: use a nearby solo terminal, red field or helicopter. Staircases are entered by walking in, never with E. All terminals in a room share one exact question, rubric and task scope. Each station has its own private answer, tutoring, completion and reward. NPC thinking speed uses this shared question’s topic, depth and rubric coverage together with the survivor’s expertise; no room question means no simulated solve progress. Local practice questions are prepared without a connector; live generation happens once per room when requested, including simultaneous station requests and exact retries after reload.
- Esc: pause/resume, including while typing. The pause menu can restart while retaining learning progress and archiving unfinished work.
- After death or extraction the building continues running and can be watched: **Watch the building** on the end card hides it and shows every occupant of the floor with no fog or lighting mask. WASD/arrows or a mouse drag pan the camera, the wheel zooms, and the floor buttons (1–4, ROOF) jump between floors instantly. **Run summary** or Esc brings the end card back. The camera is page state only; world events and saves continue. Use Pause to freeze the spectator simulation.

Fresh runs contain no equipment items or loot caches. They do contain movable office furniture: every room has an office function with its own furniture, placed clear of every field opening and terminal (see [Office building and furniture](#office-building-and-furniture)). The access panel shows keys. All survivors move at 3.3 units/second; zombies move at 1.65, including during surges. In fresh playable runs, after 180 simulation seconds one zombie arrives every three seconds from the outside lane when space permits, capped at 180 living zombies. Legacy saved runs retain their old spawn cadence and cap. Dead zombie bodies are removed at the next spawn check, and vacancies are replenished. Physics, congestion and route calculations determine performance as well as RAM; measure with `npx tsx scripts/benchmark-swarm.ts` and `npx tsx scripts/benchmark-swarm.ts --dense` (synthetic worlds only, engine timing without rendering).

NPCs can attempt a deliberate loop when ordinary retreat has left them without physical terminal work for 20 seconds. They try to draw pursuit away, approach through a clear side route, and use short work windows while retaining their puzzle progress. They use only visible/recently seen threats and remembered terminals; keys, field collisions, damage and death still apply. After 14 seconds without a work opening, they fall back to ordinary retreat with a six-second retry delay. This is an attempt to make useful progress under pressure, not a guarantee of escape.

The loop planner checks at most eight perceived threats and 16 side-route candidates plus a direct return, with expensive decisions at most once per second per NPC and staggered starts. Immediate danger still interrupts work between decisions. `npx tsx scripts/benchmark-study-loop.ts` measures planner overhead for 20 stalled NPCs with 600 zombies present; `scripts/benchmark-swarm.ts --dense` measures the full headless engine separately.

Fields have 600 HP at the main entrance, 1,200 HP at room entrances and 900 HP at forward openings. They never regenerate after a breach. Visible damaged fields show a proportional health bar; the fill fades and fracture marks increase as health falls. Critical health highlights the bar in amber while the field itself stays green/red to communicate personal access. The bar is a field's only status: the one caption a field carries is "KEY REQUIRED", shown when the field is red for you and you hold no key. Walls and character bodies remain solid.

Staircases are real wells cut into the north wall (ascending) and south wall (descending) of each fresh floor, drawn as treads between two strings. Walk into the well to take the stairs; there is no key to press. A locked staircase (no personal access on that floor) refuses you at the threshold and says why. A flight takes two simulation seconds, preserves its state across save/reload, and is cancelled by stepping back out of the well (or being pushed out); walking around inside the well does not cancel it. A blocked landing delays arrival until space is available. Arriving inside the other floor's well never starts the return flight by itself. Four passengers board each helicopter; later pickups remain available.

In-world labels are minimal: the object you hold or can reach shows only its name (for example ARMCHAIR), with no highlight box, key hints or damage words. Light furniture (chairs, plants, boxes, coolers, whiteboards, an armchair) is pushed simply by walking into it; a desk, sofa, table, cabinet or fridge holds against a walking survivor and must be gripped with E to drag or pivot. Zombies push furniture by walking into it the same way, with their own lower push.

Text fields, dropdowns and other focused controls keep their keyboard input; they cannot trigger movement or equipment shortcuts. Opening the pause menu clears held movement and freezes the simulation. Settings and agent inspection are subpages of that modal dialog; Close, Done, Back, or Esc returns to the pause menu, then Resume or Esc restores gameplay. Study in the ChatGPT tab while the game continues; pause the game explicitly when needed. The frozen request and final attributed transcript are saved in the game. A terminal is consumed after completion. Its read-only record persists.

Terminals follow the curriculum but no longer walk one branch for a whole run (`src/topic-spawn.ts`). The scheduler still names exactly one formal visit; a topic is not spawned again while it is among the last two spawns on its track when an alternative exists, and topics with open recorded gaps come back first once they have cooled. The role profile filters future PE scheduling; unticking random practice topics alone does not change formal advancement requirements. Variety terminals carry a practice contract: they probe and record knowledge, but never bind the scheduled visit, create a learning attempt or receive formal assessment. The formal visit stays reachable, and a bound visit or due review is never displaced. The game applies a valid native completion through the once-only reward path. A recorded gap never becomes mastery. Only human-authored answers enter the captured solution; tutor assistance remains attributed, and separate assessment determines academic evidence.

Knowledge probes retain named findings in `study.knowledgeGaps` and `study.knowledgeEstablished` across runs. A correct answer can establish a facet it necessarily depended on as `implied`; explicit missing knowledge is recorded as a gap, and unasked siblings remain unknown. A directly relevant prerequisite may be declared one level below a named facet, without recursive expansion. A recorded gap closes once that facet is established later, and the facet it blocked is asked again rather than inferred from its parts. Live generation receives these records as `probeRecords`, so future questions can target open gaps within the eligible scope.

Game diagnostics are stored locally in this browser, separately from learning saves. Only the newest three games are retained, each capped at 400 entries and 256 KB. They are for agents to diagnose, not for download: read them from IndexedDB (`dead-air-durable-state` → `saves` → `recent-game-diagnostics-v1`) or `window.__deadAir.logs()` on the game page. ## Visibility

You see in all directions around the survivor, with a finite radius: 11 tiles in lit areas, 8 in dim areas, and 5.4 in darkness. Heading does not restrict sight. Only walls occlude the player view. Doors and non-wall objects, including furniture, are see-through whether open, closed or intact. This is visual transparency; physical barriers still control movement, terminal reach and projectiles. The camera follows the survivor at a scale that keeps the whole sight circle visible. The entire world rendering is clipped, including character names, terminal glow and furniture placement previews. Prior exploration does not reveal current activity behind walls. Normal and Surge palettes share exactly the same visibility rules. Nearby terminal use and loot collection also require unoccluded access; a blocked terminal preserves its draft for return.

## Office building and furniture

The building is drawn as an office: carpeted study rooms, vinyl corridors and lit walls, with recognisable top-down furniture. All of it is procedural; there are no bundled art files ([sources and techniques](docs/OFFICE_ART.md)). Each run gives every room an office function, chosen at random from the run seed:

- **open-plan cubicles:** the terminal-dense rear hall, with partitions between terminal desks, plus pods of desk, chair, panels and pedestal;
- **break room:** a counter with coffee maker, microwave, fridge or water cooler, a vending machine, and cafe tables with chairs;
- **meeting room:** a conference table with chairs, a whiteboard and a wall screen;
- **storage/copy room:** shelving, filing cabinets, a copier and archive boxes;
- **manager's office:** a desk with guest armchairs, shelf and plants;
- **reception:** a front desk, sofa group and plants.

An object only ever appears in rooms of its own category; a coffee maker is always in a break room. Fresh floors hold dozens of pieces. Every piece is an ordinary movable physical object with its own health, kept clear of every field opening so no piece can seal an entrance. This supersedes the earlier no-movable-furniture rule for fresh runs. Legacy layouts keep their historical staged furniture. Heavy furniture now genuinely blocks zombies: a crowd must break it, not shove it. Chairs, office chairs and plants are lighter than one zombie's push and get shoved aside. The design decision has the measurements, including a friction bug in planck 1.5.1.

## Controlled defense measurements

`npm run benchmark:defense` exercises three seeded layouts at the actual 30 Hz simulation step. A single human physically walks, pushes/pulls ordinary furniture, operates doors, vaults and reaches a terminal while survival runs. It compares a closed door, an outer fridge, two inner shelves and the combined layers, with small placement offsets. Normal outside-only spawns, movement, damage and recurring Surge stay active. The horde is explicitly given the stationary survivor's location, so concealment cannot manufacture a successful siege.

Reports include preparation/study duration, remaining cover, damage gaps and the source/configuration hash. A layered survival result fails the benchmark if the horde stops damaging furniture or the survivor for more than 45 seconds. These are controlled physics measurements, not proof of arbitrary novice setups, full NPC strategy or enjoyable long sessions. The coarse 0.1-second historical report is retained separately from current 30 Hz measurements. Shelves in new runs have 3,200 HP: an initial 2,600-HP real-time trial left only four HP after 30 minutes, too small a reserve for the requested generous opportunities. Existing saves retain their object durability.

## Optional diagnostic and legacy code execution

The current game tab has no editor or Run button. The retained scoped runtime API can execute eligible captured work for diagnostics and legacy records; code discussed in native chat is not automatically run or treated as executed evidence. To use that runtime, install/start Docker, then install the ordinary images explicitly:

```sh
docker pull python:3.12-alpine
docker pull node:22
# Optional browser/React runtime, pinned base and package lock:
docker build -t zombie-escape-browser-runtime:0.1.0 scripts/browser-runner
node scripts/preflight-browser-runner.mjs
npm run test:runner
npm run test:browser:runner
```

The relay resolves each installed image to an immutable image ID before running; it never pulls an image during a submitted job and never falls back to executing on the host. `CODE_RUNNER_PYTHON_IMAGE` and `CODE_RUNNER_NODE_IMAGE` may select trusted installed alternatives. Runtime requests require an issued task that requests the language and matches the human's eligible curriculum scope at D2 or above. Default D1 practice remains reasoning work. Eligible live tasks can come from the ChatGPT handoff or the optional native adapter. Genuine native Study Mode identity remains unverified; automated runtime examples use isolated synthetic curriculum fixtures.

Runs use a non-root UID, a read-only root filesystem, no network, no host mounts or Docker socket, dropped capabilities and no new privileges. CPU, memory, process count, temporary storage, wall time and output are bounded; one relay job runs at a time. See the [Docker container options](https://docs.docker.com/engine/containers/run/) underlying these controls. Errors, limits and unavailable Docker stay visible.
